1. What is a firewall?

A firewall is a security control that monitors and filters network traffic according to a set of rules. It can allow permitted communications and block traffic that does not meet the rules.

Firewalls can protect a computer, a network boundary, a cloud environment or separate sections of an organisation's network.

What a firewall can do

  • Allow or block traffic based on addresses, ports, protocols, connection state or application rules.
  • Restrict access to servers and network services.
  • Help separate public-facing systems from private internal systems.
  • Record events that can help with monitoring and investigation.

What a firewall cannot guarantee

  • It cannot stop every insider threat or malicious action by an authorised user.
  • It cannot inspect traffic that does not pass through it.
  • It does not replace endpoint protection, secure configuration, patching, authentication or user awareness.
  • Allowing encrypted HTTPS traffic does not automatically mean its contents have been inspected.

Key idea: A firewall is one layer of defence, not complete security on its own.

2. Types of firewalls

Packet-filtering firewall

Checks packet header information such as source IP, destination IP, protocol and port number. A basic packet filter does not necessarily remember previous packets.

Stateless firewall

Evaluates each packet independently against its rules. It is relatively simple, but it does not track the context of an established conversation.

Stateful inspection firewall

Keeps a state table of active connections. It can recognise whether a packet belongs to a permitted, established communication session.

Circuit-level gateway

Checks connection/session establishment and whether a session is legitimate. It generally does not inspect application data in the same depth as an application proxy.

Application-level gateway (proxy firewall)

Acts as an intermediary for application traffic and can inspect application-level information, such as web requests.

Next-generation firewall (NGFW)

Combines traditional firewall controls with deeper traffic inspection and additional security capabilities. Depending on the product, these may include application awareness, intrusion prevention and malware-related controls.

3. Firewall deployment and configurations

  • Hardware firewall: a physical appliance protecting traffic between networks.
  • Software/host firewall: runs on an individual computer or server, such as Windows Defender Firewall.
  • Cloud firewall: firewall controls delivered or managed in a cloud environment.
  • Virtual wire: an inline deployment that can pass traffic without requiring the firewall to act as a conventional routed hop.
  • Layer 2: operates at the data-link layer and can filter bridged traffic.
  • Layer 3: operates with IP routing and can apply filtering to routed traffic.
  • Edge protection: controls traffic entering or leaving an organisation's network.
  • Internal segmentation: restricts traffic between internal network zones.

DMZ (demilitarised zone)

A DMZ is a separate network zone for systems that need to be reachable from less-trusted networks, such as public web servers. It helps prevent direct access from the internet to the private internal network.

Example: allow internet users to reach the public web server on TCP 443, while denying direct internet access to internal staff devices.

4. Firewall rules, ACLs and rule order

A firewall rule can use a combination of:

  • Source IP address and destination IP address
  • Protocol (for example TCP, UDP or ICMP)
  • Source and destination ports, where applicable
  • Application, connection state, interface or time schedule (depending on the firewall)
  • Action: allow, deny or drop, and sometimes log

How rule processing works

  1. Rules are commonly checked from top to bottom.
  2. The first matching rule determines the action in a first-match rule set.
  3. Put specific rules before broad rules so a broad rule does not override the intended exception.
  4. An implicit deny means traffic not matched by an allow rule is denied by default.
  5. An explicit deny-all rule at the bottom can make the policy visible and may support logging, depending on the platform.

Common ports from the workshop

  • 22/TCP: SSH remote administration
  • 25/TCP: SMTP mail transfer
  • 53: DNS (commonly UDP, also TCP)
  • 80/TCP: HTTP web traffic
  • 123/UDP: NTP time synchronisation
  • 443/TCP: HTTPS web traffic
  • ICMP: network control and diagnostic messages; it does not use TCP/UDP port numbers.

Do not open a port to everyone unless the service genuinely needs to be publicly reachable. Restrict management access, define source addresses where possible, log appropriately and use default-deny policies.

5. NAT and firewalls

Network Address Translation (NAT) changes address information, commonly translating private internal addresses to a public address for internet access. A NAT device may keep translation information so return traffic can be directed to the correct internal device.

NAT is not the same as a firewall. NAT performs address translation; a firewall applies a security policy to traffic. A device can provide both functions, but they are conceptually different.

6. Threats and firewall protections

  • IP spoofing: an attacker forges a source IP address. Ingress and egress filtering can reject traffic with impossible or inappropriate source addresses.
  • SYN flood: an attacker sends many TCP connection-start requests to exhaust connection resources. Defences can include SYN cookies/proxies, rate limits, connection limits and upstream DDoS protection.
  • Botnet DDoS: many compromised devices send traffic towards a target. Filtering and rate limiting may help, but large attacks often need upstream provider or specialist DDoS mitigation.
  • SYN+FIN and NULL scans: unusual TCP flag combinations can be used in reconnaissance. They may be logged or filtered, but results vary by operating system and network device.

Firewall controls should be combined with IDS/IPS, endpoint detection and response (EDR), secure configuration, patching and monitoring.

7. IDS, IPS and monitoring

  • IDS – Intrusion Detection System: monitors activity and raises alerts about suspicious behaviour.
  • IPS – Intrusion Prevention System: can take action to block or prevent detected malicious traffic.
  • EDR – Endpoint Detection and Response: monitors endpoint activity and supports investigation and response.

Detection is not perfect: systems can produce false positives (benign activity incorrectly flagged) and false negatives (malicious activity missed). Alerts need investigation and tuning.

8. Practical activities and tools

Windows Defender Firewall

Explore the Windows Firewall profiles and inbound/outbound rules. Review which applications are allowed and why. Do not disable protection on a device you rely on.

O&O ShutUp10

This is a Windows privacy-configuration utility, not a replacement for Windows Defender Firewall or a network firewall. Review recommendations carefully; changing privacy settings can affect Windows features. Use the official vendor website and consider creating a restore point before significant changes.
