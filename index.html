TCP/IP Troubleshooting: My Network Engineer Cheat Sheet

CC6004 Network and Cloud Security - Week 4

1. Introduction

TCP/IP is a collection of networking protocols that allows computers and other devices to communicate across networks and the internet. Understanding TCP/IP helps network engineers identify connection problems, investigate network traffic and improve security.

The Four TCP/IP Layers

Layer Purpose Examples
Application Provides network services to applications. HTTP, DNS, DHCP, SNMP
Transport Transfers data between applications. TCP, UDP
Internet Addresses and routes packets between networks. IPv4, IPv6, ICMP
Network Access Moves data over the local network connection. Ethernet, Wi-Fi

The OSI model has seven layers and is a reference framework for understanding how network communication works.

2. Network Command Cheat Sheet

Command Purpose Safe example What to look for Limitation
ipconfig Displays Windows IP configuration. ipconfig IP address, subnet mask and default gateway. Does not prove internet connectivity.
ping Tests whether a destination responds. ping example.com Replies, packet loss and response time. Some systems block ping, even when services work.
netstat -an Shows network connections and listening ports. netstat -an Listening ports and connection states. Does not identify every security vulnerability.
tracert Shows the route towards a destination on Windows. tracert example.com Network hops and where responses stop. Routers may not respond to tracing probes.
nslookup Checks DNS name resolution. nslookup example.com Whether a name resolves to an IP address. One lookup does not test the whole website.

On Linux, alternatives include ip, ss and traceroute. Commands and output can differ between operating systems.

3. Cloud Tools I Explored

  • Google Public DNS lookup — investigates DNS records for domain names.
  • Online PCAP Viewer — helps inspect packet captures and network headers. Only use public sample captures or files you are authorised to inspect.
  • IP Information — shows information about the public IP address used for an internet connection. Do not publish your actual IP.

These tools help investigate DNS, IP addressing and packet information. Results should be interpreted alongside other evidence rather than treated as proof of a complete diagnosis.

4. My Five-Step Troubleshooting Process

  1. Check IP configuration: Confirm that the device has an appropriate IP address, subnet mask and default gateway.
  2. Check DNS: Use nslookup to see whether the domain name resolves correctly.
  3. Test connectivity: Use ping where appropriate. Remember that blocked ping responses do not always mean a network is down.
  4. Check the service: Confirm that the website uses HTTPS and investigate service or port availability using authorised methods.
  5. Record and review: Document the symptoms, commands, results and actions taken. If unresolved, escalate with the evidence collected.

5. My Learning Reflection

During Week 4, I learned about the TCP/IP model and how its four layers support communication between devices. I learned that DNS translates domain names into IP addresses, while TCP provides reliable, connection-oriented data delivery. I also explored the difference between IPv4 and IPv6, private and public IP addresses, and the role of NAT in translating addresses between networks.

One challenge was understanding how to use network commands and interpret their results. I learned that ping can help investigate connectivity, but a failed response does not necessarily mean that a destination is unavailable. I also learned that DNS problems and website service problems need to be investigated separately. The workshop tools and learning materials helped me understand these concepts more clearly.

These skills are relevant to network security because engineers need to troubleshoot communication problems, understand network traffic and identify exposed services. I want to practise more so that I can interpret results confidently and explain my findings clearly. I will use authorised lab environments and avoid sharing sensitive network information.
